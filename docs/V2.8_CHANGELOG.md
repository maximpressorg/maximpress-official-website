# V2.8 — Login, navigation gating, privacy & review engagement

* Baseline: owner-supplied `MaxImpress_V2.7.zip`; existing testimonials and quote strings unchanged.
* Login: concise central official-style form; Google and Apple provider buttons precede email fields. Google OAuth uses Firebase's actual provider popup/redirect, not a fake consent screen. Apple is disabled until configured.
* Access: Home, About, Privacy, Terms and Account are the only informational pages available before authentication in the client-side interface. Signed-in verified users see original project links and services. Other marketing and portfolio pages redirect to registration, with a return link saved across onboarding. On Home, guest hero/header displays Log In and Sign Up.
* IMPORTANT SECURITY LIMIT: JavaScript route gating is an interface restriction only. Firebase Hosting delivers static HTML publicly; users or crawlers can directly download HTML/asset files, including any embedded prices. Do not treat pricing or content as protected. To enforce server-side confidentiality, move restricted data to callable authenticated backend or private Firestore-backed rendering and remove it from static HTML.
* Consent: small single-decision privacy choice remembered in localStorage. Essential vs optional Analytics; GA4 only starts with opt-in. Footer choice link allows revisiting preferences. Existing privacy/terms documents preserved.
* Intro: premium plum-purple-pink locally animated logo splash, no skip, no fake loading UI; shown one time per browsing session and auto-dismisses.
* Review engagement: genuine like/dislike votes and pending-comment submissions, stored in Firestore per verified customer. Live vote counts begin at **zero** and grow with real usage. Same customer has only one active reaction per review; clicking an active reaction removes it. Comment moderation section appears on Owner Admin page. Firestore rules constrain voting and comments. Real ratings can be supplied in `public/assets/review-ratings.json`, but only after verifying source records. Unknown ratings remain visibly unscored.
* No fabricated 600–1500 likes, dislikes or 3.5–5.0-star ratings have been added. No invented Trustpilot/Google endorsement was introduced. The V2.7 existing badges were left untouched, though historical documentation says their underlying platform records have not been independently verified.
* Feedback submissions now create Firestore records under `reviewSubmissions` pending moderation; admin review/approve/reject UI added. Approved submissions appear below existing 16 unchanged reviews and accept genuine signed-in reactions/comments. Database and OAuth still require external configuration.
* Requires a real Firebase project, authorized domain, identity providers, Firestore rules publication and appropriate moderation. Not deployed or live-tested here.

## V2.8 follow-up refinements
- Signup automatically authenticates the new email/password user through Firebase. Before proceeding to onboarding/dashboard, the account must verify its email. Google/Apple users are automatically authenticated after successful provider authorization.
- Passwords: removed former custom 12-character, uppercase/lowercase/digit policy. Firebase's default mandatory six-character minimum remains. It cannot be set to zero through Firebase. Owner-configured stronger Firebase password policies may still apply.
- Original 16 review texts and source badges were not edited. Unverified star ratings remain unscored; the genuine system starts at zero likes/dislikes and records actual signed-in interactions. Do not generate artificial reviews, ratings, votes, or endorsements.
- Mobile menu project CTA no longer appears before login; authenticated menu receives it dynamically. Home/About public project CTAs route to Sign Up for guests.
- Complete Google OAuth and Apple developer accounts must be configured by owner; browser integration code alone cannot activate either provider.
